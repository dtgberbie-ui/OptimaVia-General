Build the login screen and the main dashboard for OptimaVia General. This is a mobile-first small business operations platform. The app serves different business types using the same core but with different modules toggled on. I have two initial business types:

1. **Field Service** (e.g., Filta Raleigh — dispatches workers to client locations)
2. **Product-Based** (e.g., an ice cream shop — tracks costs, recipes, pricing)

I need the login page and the dashboard that adapts based on the business type.

---

## Tech Stack

- React + TypeScript
- Tailwind CSS
- Node.js + Express backend
- PostgreSQL (use Replit's built-in DB or Drizzle ORM)
- Mobile-first responsive design (optimize for 375px phone width, scale up gracefully)

## Data Model (minimum needed for these screens)

```sql
-- Businesses
CREATE TABLE businesses (
  id SERIAL PRIMARY KEY,
  name VARCHAR(255) NOT NULL,
  type VARCHAR(50) NOT NULL, -- 'field_service' or 'product'
  active_modules TEXT[] DEFAULT '{}',
  created_at TIMESTAMP DEFAULT NOW()
);

-- Users
CREATE TABLE users (
  id SERIAL PRIMARY KEY,
  business_id INTEGER REFERENCES businesses(id),
  first_name VARCHAR(100) NOT NULL,
  last_name VARCHAR(100) NOT NULL,
  email VARCHAR(255) UNIQUE NOT NULL,
  password_hash VARCHAR(255) NOT NULL,
  role VARCHAR(20) NOT NULL DEFAULT 'employee', -- 'owner', 'manager', 'employee'
  status VARCHAR(20) DEFAULT 'active',
  created_at TIMESTAMP DEFAULT NOW()
);

-- Jobs (for field service)
CREATE TABLE jobs (
  id SERIAL PRIMARY KEY,
  business_id INTEGER REFERENCES businesses(id),
  title VARCHAR(255),
  client_name VARCHAR(255),
  location_address TEXT,
  scheduled_date DATE,
  scheduled_time TIME,
  assigned_to INTEGER REFERENCES users(id),
  status VARCHAR(20) DEFAULT 'unassigned', -- 'unassigned', 'assigned', 'in_progress', 'completed'
  priority VARCHAR(10) DEFAULT 'medium',
  key_tracking_enabled BOOLEAN DEFAULT false,
  notes TEXT,
  started_at TIMESTAMP,
  completed_at TIMESTAMP,
  created_by INTEGER REFERENCES users(id),
  created_at TIMESTAMP DEFAULT NOW()
);

-- Expenses
CREATE TABLE expenses (
  id SERIAL PRIMARY KEY,
  business_id INTEGER REFERENCES businesses(id),
  user_id INTEGER REFERENCES users(id),
  amount DECIMAL(10,2) NOT NULL,
  category VARCHAR(100),
  description VARCHAR(255),
  date DATE NOT NULL,
  receipt_photo_url TEXT,
  created_at TIMESTAMP DEFAULT NOW()
);

-- Revenue
CREATE TABLE revenues (
  id SERIAL PRIMARY KEY,
  business_id INTEGER REFERENCES businesses(id),
  user_id INTEGER REFERENCES users(id),
  amount DECIMAL(10,2) NOT NULL,
  source VARCHAR(255),
  product_id INTEGER,
  date DATE NOT NULL,
  note TEXT,
  created_at TIMESTAMP DEFAULT NOW()
);

-- Ingredients (for product costing)
CREATE TABLE ingredients (
  id SERIAL PRIMARY KEY,
  business_id INTEGER REFERENCES businesses(id),
  name VARCHAR(255) NOT NULL,
  unit VARCHAR(50),
  cost_per_unit DECIMAL(10,4),
  supplier VARCHAR(255),
  created_at TIMESTAMP DEFAULT NOW()
);

-- Products
CREATE TABLE products (
  id SERIAL PRIMARY KEY,
  business_id INTEGER REFERENCES businesses(id),
  name VARCHAR(255) NOT NULL,
  description TEXT,
  category VARCHAR(100),
  selling_price DECIMAL(10,2),
  created_at TIMESTAMP DEFAULT NOW()
);

-- Product ingredients (recipe)
CREATE TABLE product_ingredients (
  id SERIAL PRIMARY KEY,
  product_id INTEGER REFERENCES products(id),
  ingredient_id INTEGER REFERENCES ingredients(id),
  quantity_per_unit DECIMAL(10,4)
);

-- Notifications
CREATE TABLE notifications (
  id SERIAL PRIMARY KEY,
  business_id INTEGER REFERENCES businesses(id),
  user_id INTEGER REFERENCES users(id),
  message TEXT NOT NULL,
  type VARCHAR(50),
  read BOOLEAN DEFAULT false,
  created_at TIMESTAMP DEFAULT NOW()
);
```

The dashboard page checks the logged-in user's business type and active_modules to decide which variant to render (field service stats + jobs list OR product margins + expenses list). Use the same React component with conditional rendering based on the business type — NOT two separate pages.

## Important Implementation Notes

- **Mobile-first:** Design for 375px width. The dashboard should look great on a phone. Use max-width container centered on desktop but don't worry about desktop optimization yet.
- **The bottom nav bar** should be fixed at the bottom of the viewport so it's always accessible as the user scrolls.
- **Stat card values** should be computed from actual database records (sum of revenue entries, sum of expense entries for the current month). For "Active jobs" count jobs that are not "completed". For "Team in field" count employees with at least one "in_progress" job today. For "Avg margin" compute the average margin across all products.
- **Product margins** should be calculated from the product_ingredients join — sum(ingredient.cost_per_unit * product_ingredient.quantity_per_unit) for each product, then compute margin as (selling_price - cost) / selling_price * 100.
- **The alert bar** should pull from unread notifications of type "key_alert". Only show it if there are unread alerts.
- **"Today's jobs"** filters jobs where scheduled_date = today, sorted by scheduled_time ascending. Show max 3 on dashboard.
- **"Recent expenses"** shows the 3 most recent expense entries for the business.
- **Time-based greeting:** "Good morning" before noon, "Good afternoon" before 5pm, "Good evening" after 5pm.
- **Date display:** Show the current actual date, formatted like "Thursday, Apr 4".
- **All monetary values** should be formatted with dollar sign and two decimal places (except stat card totals which can be rounded to whole numbers).
- **Percentage values** should be rounded to whole numbers (no decimal).
