# Employee Database — Part 1: Database Setup & Module Toggle

## What to do

Add the database tables and module toggle for a new "Employee Database" feature. Do NOT build any UI yet — just the backend.

## Database changes

Add these new tables:

```sql
CREATE TABLE employee_profiles (
  id SERIAL PRIMARY KEY,
  user_id INTEGER REFERENCES users(id) ON DELETE CASCADE UNIQUE,
  date_of_birth DATE,
  street_address VARCHAR(255),
  city VARCHAR(100),
  state VARCHAR(50),
  zip_code VARCHAR(20),
  job_title VARCHAR(100),
  employment_type VARCHAR(20) DEFAULT 'full_time',
  start_date DATE,
  end_date DATE,
  pay_rate DECIMAL(10,2),
  pay_type VARCHAR(10) DEFAULT 'hourly',
  department VARCHAR(100),
  profile_photo_url TEXT,
  emergency_contact_name VARCHAR(255),
  emergency_contact_phone VARCHAR(50),
  emergency_contact_relationship VARCHAR(50),
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);

CREATE TABLE employee_notes (
  id SERIAL PRIMARY KEY,
  user_id INTEGER REFERENCES users(id) ON DELETE CASCADE,
  author_id INTEGER REFERENCES users(id),
  note TEXT NOT NULL,
  created_at TIMESTAMP DEFAULT NOW()
);
```

Update the users table to support a third status option. Currently it has 'active' and 'inactive'. Add 'terminated' as a valid status.

## Module toggle

In the business settings where modules are toggled on/off, add a new option:
- **"Employee Database"** → ON/OFF
- When toggled ON, add `'employee_database'` to the business `active_modules` array
- When toggled OFF, remove it

## API endpoints to create

```
GET    /api/employees              — list all employees for the business (with profile data)
GET    /api/employees/:id          — get single employee with full profile
POST   /api/employees              — create new employee + profile
PUT    /api/employees/:id          — update employee profile
PATCH  /api/employees/:id/status   — change status (active/inactive/terminated)
POST   /api/employees/:id/notes    — add a note to an employee
GET    /api/employees/:id/notes    — get all notes for an employee
```

All endpoints require authentication. Only owner/manager roles can access them (except employees can GET their own profile).
